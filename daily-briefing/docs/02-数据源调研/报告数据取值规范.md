# 报告数据取值与质量规范（美股 / A股 / 港股）

> 目的：统一每天报告的数据取值来源，避免再犯「指数点位估算、港股字段推断错、数据口径混乱」等问题。
> 背景教训：2026-08-28 美股 8/28 报告用 WebSearch 媒体摘要点位导致三大指数偏低（道 53558 vs 真实 53559.99）、费半写"11,905 附近"估算；港股曾把新浪 `rt_hk` 的"今开"[2]误当"现价"算涨跌幅，导致涨跌方向全反。

---

## 一、美股

### 指数点位（必须权威，禁止估算）
- 道指 / 标普500 / 纳指 / 罗素2000：用 **FMP `historical-price-eod/full`**（权威 EOD）或 **新浪 `hq.sinajs.cn`（gb_$dji / gb_ixic / gb_inx / gb_$rut）**、**Yahoo（^GSPC / ^IXIC / ^DJI / ^RUT）**。
- ❌ **禁止**用 WebSearch 媒体摘要的点位（经验：会偏低）；❌ 禁止写"11,905 附近"这类**估算**。

### 费城半导体指数（^SOX）
- FMP 免费档 `^SOX` **取不到**（返回 None）→ 改用 **Yahoo `^SOX`** 或 **新浪 `gb_$sox`**（实时=最新收盘）。
- ❌ 禁止写"XX 附近"估算；必须给精确收盘。

### 涨跌幅口径
- 指数/板块用**市值加权/官方**口径为主（媒体 / FMP）。
- ⚠️ **Infoway 是等权口径**（如标普等权 -0.09% vs 市值加权 -0.26%，数值不同）。引用 Infoway 数据必须**标注"等权口径"**，不要与加权值混用。

### 全市场行业热力（`industry_heat`）
- 主源：**FMP `/stable/industry-performance-snapshot?date=YYYY-MM-DD&exchange=NASDAQ|NYSE`**。
- NASDAQ 与 NYSE 必须**分交易所调用**，同名行业再用两次结果做等权平均；不能把两个交易所的行简单相加。
- 口径固定为：**FMP 成分股等权平均，NASDAQ+NYSE 合并**。它不是市值加权行业指数，也不能与费半、标普500行业指数互相换算。
- 中文行业名只能来自 `daily-briefing/scripts/industry_mapping.json`；缺失映射显示英文原名，不得现场猜中文名。
- 报告只需展示 `top` / `bottom` / `tech_focus`，除非用户要求完整表；所有数字来自 JSON 快照，禁止用网页截图或媒体榜单替换。

### Invest Wiki 产业链段热力（`chain_heat`）
- **宇宙来源**：`daily-briefing/scripts/chain_universe.json`（Invest Wiki 编译产物的消费侧快照，非本地手工维护）。该文件含 `version`、`logic_version`、`source_sha256`、`source_commit` 四项元数据，**每次运行前必须校验非空并记录进报告**；上游更新产业链内容时，只需把固定 commit URL 换成新版本重下，不要去抓 Invest Wiki 的网页 DOM。
- **段数口径**：原始 81 段合并跨赛道重名后为 **canonical 段**（当前 65 段）。**全部段都参与计算**，报告只展示 **Top 8 / Bottom 8**。
- **行情源**：**Yahoo Finance（yfinance）为主**；FMP 只作个股/市值补充，不再走旧的 `chain_map.json` 逐只 `quote` 链路。
- **排序口径**：**等权 `change_equal_weight_pct` 为主**（反映整段广度），市值加权 `change_mcap_weight_pct` 只作参考（反映大市值龙头影响）。⚠️ 与旧版（`chain_map.json` 时代以市值加权为主）口径相反，引用历史报告时注意区分。
- **去重**：段内同一 ticker 只计一次；AI算力/半导体大赛道汇总与全局汇总**同样按 ticker 去重**。因此**段涨跌不能相加或平均成"AI全链涨跌"**。
- **排名门槛**：仅 `n_used >= 2`（`rankable`）的段参与排名；样本不足的段保留在 JSON 但不排名。
- **A股映射**：只是"美股段 → A股观察参考"，**不参与海外热力计算**；除非当日另有 A股快照，否则禁止写 A股当日涨跌幅。
- **异常股**：链内 `|chg_pct| ≥ 5%` 的成分股全量写入 `anomalies_pct_5`，必须保留所属段上下文。
- **必须标注的例外**：`n_missing > 0`、`date_mixed=true` 时报告须简要标注；取不到的标的标 `[缺失]`，不得硬凑。
- **产物**：`data/industry_chain_heat_YYYY-MM-DD.json`（日期用美东行情交易日，非报告发布日）。

## 二、A股

### 指数点位
- 用腾讯K线（`stock_zh_index_daily_tx`）/ 新浪直连，权威。

### 港股指数（高危，曾翻车）
- 新浪 `rt_hk` 原始数组字段顺序（务必记住）：
  **`[0]代码 [1]名称 [2]今开 [3]昨收 [4]最高 [5]最低 [6]现价(收盘) [7]涨跌额 [8]涨跌幅`**
- ❌ **严禁把 `[2]今开` 当 `[6]现价/收盘`** 去算涨跌幅（曾导致恒指/国企/科技**涨跌方向全反**）。
- 已修复：`fetch_a_share_data.py` 的 `fetch_hk` 现返回规范化字段 `{price, prev_close, change_pct}`，直接用。

### A股板块涨跌数据源（调研结论，详见《板块涨跌数据源调研-A股科技概念.md》）
| 源 | 板块数 | 语言 | 稳定性 | 有无科技概念(AI算力/机器人/半导体) |
|----|--------|------|--------|--------------------------------|
| **新浪行业**(`stock_sector_spot`) | 49 | 中文 | ✅ | ❌ 仅电子器件≈半导体 |
| **Infoway**(`plate/industry/CN`) | 132 | 英文GICS | ✅ | ⚠️ 有半导体行业，无AI算力/机器人**概念** |
| 东财概念(`stock_board_concept_name_em`) | 多 | 中文 | ❌反爬不稳 | ✅ **有** AI算力/机器人/半导体 |
- 板块图**优先新浪行业板块**（中文、稳定）；科技概念需**东财概念**（反爬不稳，需重试/兜底）或**自建合成**。

## 三、通用规范

1. **数据源字段含义必须权威源交叉验证**后才写报告，不凭接口返回猜。
2. **口径标注**：媒体 vs API、加权 vs 等权、`[公开口径]` 等必须写清，避免读者/自己误解。
3. **`[待核实]`**：仅用于真正取不到/来源冲突的字段；能用权威源拿到的绝不标待核实、不写估算。
4. 图表坐标轴、点位、涨跌幅统一标准；`buildOverviewCard` 从报告表格取数画图，表格数据必须来自权威源。

## 四、回查修正案例（2026-08-28 美股）

**触发**：用户反馈美股 8/28 报告"指数数据不对"。回查发现几类问题并已全部修正：

1. **指数点位偏低**：报告用 WebSearch 媒体摘要（道 53558.38 / 标普 7711.05 / 纳指 26400.56），低于 FMP/新浪权威收盘（道 53559.99 / 标普 7711.76 / 纳指 26402.42）。修正 = 统一用权威值。
2. **费半"附近"估算**：8/28 报告费半写"11,905 附近"，实际 8/27 费半 = 11882.17（Yahoo ^SOX）。修正。
3. **罗素口径小差**：8/25~8/27 罗素用了 Infoway 等权（3009.09/3009.98/3015.59），FMP 权威为 3010.02/3005.90/3014.34（差 0.9~4 点）。修正为 FMP。
4. **缺失**：us/8/25 报告缺费半行，补 11423.17（-2.70%）。

**核对方法**：FMP `historical-price-eod/full` 拉日表（8/18~8/28 权威收盘）+ Yahoo `^SOX` 拉费半历史，逐份比对报告表格。

**结论**：三大指数点位各期**本就正确**（对应正确交易日）；真正问题是费半估算/缺失 + 罗素口径差。**以后生成即用权威源，不依赖报告后回查。**
