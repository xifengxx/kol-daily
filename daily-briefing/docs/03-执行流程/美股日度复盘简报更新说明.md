## 1. 这次到底改了什么

旧版美股日度复盘的整体流程不变。最新版本只在**美股报告第四部分**新增两组数据模块：

1. **行业热力图**：使用 FMP 全市场行业口径。
2. **Invest Wiki 产业链段热力图**：使用产业链 universe JSON 计算自建产业链赛道热力。

这两块都进入报告第四部分，并共用一个“驱动解释层”，也就是对行业、产业链段和异常股补充“为什么涨/为什么跌”。

不要把这两个模块理解成同一个口径：

- 行业热力图是**交易所/行业分类口径**。
- 产业链段热力图是**Invest Wiki 自建产业链角色口径**。

两者不能互相换算，报告中必须分别标注。

## 3. 行业热力图逻辑

### 3.1 数据源

使用 FMP 接口：

```text
/industry-performance-snapshot
```

需要分别请求：

```text
exchange=NASDAQ
exchange=NYSE
```

### 3.2 计算逻辑

1. 获取两个交易所的行业当日表现。
2. 将 `NASDAQ` 和 `NYSE` 的同名行业合并。
3. 对同名行业取平均涨跌幅。
4. 用 `industry_mapping.json` 把 FMP 英文行业名映射为中文行业名。
5. 排序后报告只展示 `Top 8 / Bottom 8`。

行业数量不写死。以 `2026-09-10` 基线为例，接口返回并合并后共 `139` 个行业。

### 3.3 重要限制

FMP 免费版不返回行业成分股。因此行业热力表本身只有行业级涨跌幅，不含每个行业的成分股明细。

## 4. Invest Wiki 产业链段热力逻辑

### 4.1 技术侧只需要一个 JSON

产业链上游只需要向技术侧暴露一个产物：

```text
chain_universe.json
```

技术侧不要读取产业链网页 DOM，也不需要理解或迁入 Invest Wiki 的内部编译流程。

当前消费侧快照在：

[daily-briefing/scripts/chain_universe.json](https://github.com/xifengxx/kol-daily/blob/gh-pages/daily-briefing/scripts/chain_universe.json)

当前上游固定版本在：

[chain_universe.json @ 5a32637](https://github.com/xifengxx/invest-wiki/blob/5a32637/L3-%E7%BD%91%E9%A1%B5%E4%BA%A7%E7%89%A9/chain_universe.json)

当前基线元数据：

```text
version          = 2026-09-11.3
logic_version    = canonical-segments-v2
source_hash8     = ba099660
source_segments  = 81
canonical_segments = 65
overseas_quote_candidates = 172
a_share_mapping_companies = 89
private_or_untradable = 58
```

### 4.2 抓行情与计算

```text
chain_universe.json
      ↓
筛选海外行情候选
      ↓
使用 Yahoo / yfinance 抓取行情
      ↓
逐个产业链段计算热力
      ↓
industry_chain_heat_YYYY-MM-DD.json
```

计算规则：

- A股只作为映射观察对象，不参与海外热力计算。
- 私有或未上市公司不参与行情计算。
- 段内同一 ticker 只计算一次。
- AI算力、半导体大赛道汇总时也按 ticker 去重。
- 每个产业链段计算两个口径：
  - **等权涨跌幅**：主排序口径，反映整段股票广度。
  - **市值加权涨跌幅**：辅助口径，反映大市值龙头的实际影响。
- `n_used >= 2` 的段才参与排名；样本不足的段保留在 JSON，但不参与排名。
- 报告只展示 `Top 8 / Bottom 8`，但计算必须覆盖全部 65 个 canonical segments。

### 4.3 报告展示内容

产业链段热力报告需要包含：

- AI算力 / 半导体大赛道汇总；
- Top8 / Bottom8 产业链段；
- 每段领涨股、领跌股；
- A股映射；
- 链内异常股；
- 异常股驱动解释。

链内异常股规则：

```text
|chg_pct| >= 5%
```

满足条件的异常股全量进入展示和驱动解释流程。

## 5. 驱动解释层逻辑

驱动解释层不是从 FMP 或 universe JSON 直接得到的，而是通过新闻检索加人工/模型筛选完成。

检索对象包括：

1. FMP 行业热力 `Top 8 / Bottom 8`。
2. 产业链段热力 `Top 8 / Bottom 8`。
3. 所有 `|chg_pct| >= 5%` 的链内异常股。

当前第一层检索使用：

```text
Google News RSS
```

后续可以替换为新闻 API，但输出 schema 必须保持一致。

### 5.1 输出 schema

```json
{
  "date": "YYYY-MM-DD",
  "generated_at": "ISO8601",
  "method": "Google News RSS + human curation",
  "entries": [
    {
      "type": "industry | segment | anomaly",
      "key": "行业名 / segment_id / TICKER",
      "display": "展示名",
      "confidence": "高 | 中 | 低",
      "driver": "1-2句驱动解释",
      "sources": [
        {
          "title": "新闻标题",
          "source": "媒体名",
          "url": "URL",
          "published": "YYYY-MM-DD"
        }
      ]
    }
  ]
}
```

### 5.2 解释规范

| 置信度 | 判定 |
|---|---|
| 高 | 官方公告、财报、监管文件、权威媒体明确确认，时间和对象匹配。 |
| 中 | 有较强相关线索，但不是完全一对一确认。 |
| 低 | 无明确公开原因，只有泛化报道或情绪推断。 |

没有明确公开原因时，统一写：

```text
暂无明确公开原因。（置信度：低）
```

禁止编造订单、指引、评级、监管事件、资金流向。  
禁止混淆盘中、盘前、盘后。

## 6. 复现步骤

以下命令都假设在仓库的 `daily-briefing/` 目录下执行。

### 6.1 环境变量

```bash
export FMP_API_KEY="<your_fmp_key>"
export INFOWAY_API_KEY="<optional_infoway_key>"
```

`FMP_API_KEY` 必填。`INFOWAY_API_KEY` 可选；缺失时部分字段会标记为缺失，不阻塞报告。

### 6.2 抓市场与行业热力

```bash
python3 scripts/fetch_us_market_data.py 2026-09-10 \
  --json-out data/us_market_data_2026-09-10.json
```

### 6.3 抓产业链行情并计算热力

```bash
python3 scripts/fetch_industry_chain_heat.py 2026-09-10 \
  scripts/chain_universe.json \
  data/industry_chain_heat_2026-09-10.json
```

### 6.4 生成驱动候选

```bash
python3 scripts/fetch_daily_drivers.py \
  --date 2026-09-10 \
  --market data/us_market_data_2026-09-10.json \
  --heat data/industry_chain_heat_2026-09-10.json \
  --out data/us_drivers_raw_2026-09-10.json
```

### 6.5 人工整理驱动解释

把：

```text
data/us_drivers_raw_2026-09-10.json
```

整理成：

```text
data/us_drivers_2026-09-10.json
```

整理时必须保留：

```text
type
key
display
confidence
driver
sources
```

### 6.6 渲染热力版报告

```bash
python3 scripts/render_industry_chain_report.py \
  --base reports/us/2026-09-11-industry-chain-invest-wiki.md \
  --heat data/industry_chain_heat_2026-09-10.json \
  --out reports/us/2026-09-11-industry-chain-invest-wiki.md
```

`--base` 必须已经包含产业链章节骨架。首次生成新报告时，先准备模板；复算当天报告时，可以用当前热力版报告作为 base。

### 6.7 渲染驱动解读版报告

```bash
python3 scripts/render_drivers_report.py \
  --base reports/us/2026-09-11-industry-chain-invest-wiki.md \
  --drivers data/us_drivers_2026-09-10.json \
  --out reports/us/2026-09-11-industry-chain-invest-wiki-drivers.md
```

### 6.8 校验

```bash
python3 scripts/validate_report_data.py --market us \
  --report reports/us/2026-09-11-industry-chain-invest-wiki-drivers.md
```

### 6.9 发布

1. 更新 [daily-briefing/manifest.json](https://github.com/xifengxx/kol-daily/blob/gh-pages/daily-briefing/manifest.json)。
2. 把新报告 key 放到 `us` 数组最前。
3. 在 `us_title` 中加入报告标题。
4. commit 和 push。
5. 打开 [daily-briefing/index.html](https://xifengxx.github.io/kol-daily/daily-briefing/index.html)，选择对应日期验证。

## 7. 日期口径

这里有一个容易踩坑的地方：

| 文件类型 | 使用日期 | 示例 |
|---|---|---|
| `data/*.json` | 美东行情交易日 | `2026-09-10` |
| `reports/us/*.md` | 北京时间发布日 | `2026-09-11` |

所以 `2026-09-11-industry-chain-invest-wiki.md` 通常对应的是美东 `2026-09-10` 行情。

新增报告时，不要把所有文件都机械地使用同一个日期。

## 8. Invest Wiki 上游更新处理

当 Invest Wiki 侧更新产业链内容，例如新增、筛选、调整赛道或更新公司映射，上游会重新发布新的 `chain_universe.json`。

技术侧只需要：

1. 更新 `CHAIN_UNIVERSE_URL` 到新的固定 commit。
2. 下载新的 JSON。
3. 校验：
   - `version`
   - `logic_version`
   - `source_sha256`
   - `source_commit`
4. 继续走本仓库的行情抓取、热力计算、驱动解释和报告渲染。

除 `chain_universe.json` 外，不需要读取 Invest Wiki 的网页、内部数据或编译流程。

## 9. 验收清单

上线前逐项检查：

| 检查项 | 通过标准 |
|---|---|
| universe 版本 | `version`、`logic_version`、`source_sha256`、`source_commit` 非空且已记录。 |
| 日期一致 | `us_market_data`、`industry_chain_heat`、`us_drivers` 使用同一个美东交易日。 |
| 行业数量 | 不写死行业数量；以当日 FMP 返回为准。 |
| 产业链段数 | 全部 canonical segments 参与计算。 |
| 排名范围 | 报告只展示 `Top 8 / Bottom 8`。 |
| 去重 | 段内、大赛道汇总、全局汇总均按 ticker 去重。 |
| A股映射 | 只作为次日观察，不参与海外热力计算。 |
| 异常股 | 所有 `|chg_pct| >= 5%` 的异常股全量展示。 |
| 驱动解释 | 有来源、有置信度；无原因写“暂无明确公开原因”。 |
| 历史保护 | 不覆盖旧报告；重算只能生成新版本文件。 |
| manifest | 新报告在 `us` 数组最前。 |
| 线上验证 | 网页能加载，标题和日期正确，关键表格存在。 |
