# 美股产业链热力 + 驱动解读：数据流与运行手册

**适用报告**：美股日度复盘简报第四部分  
**基线示例**：报告文件名 `2026-09-11-industry-chain-invest-wiki.md`，行情交易日 `2026-09-10`  
**方案说明**：[`美股-InvestWiki产业链热力+驱动解读-实现与同步方案.md`](./美股-InvestWiki产业链热力+驱动解读-实现与同步方案.md)

## 1. 目录约定

所有命令都在 `daily-briefing/` 目录下执行：

```text
daily-briefing/
  data/
    us_market_data_YYYY-MM-DD.json
    industry_chain_heat_YYYY-MM-DD.json
    us_drivers_raw_YYYY-MM-DD.json
    us_drivers_YYYY-MM-DD.json
  reports/us/
    YYYY-MM-DD.md
    YYYY-MM-DD-industry-chain-invest-wiki.md
    YYYY-MM-DD-industry-chain-invest-wiki-drivers.md
  scripts/
    fetch_us_market_data.py
    fetch_industry_chain_heat.py
    fetch_daily_drivers.py
    render_industry_chain_report.py
    render_drivers_report.py
    industry_mapping.json
    chain_universe.json
```

注意：文件名里的 `YYYY-MM-DD` 有两种含义。`data/*.json` 使用行情交易日；`reports/us/` 使用北京时间发布日。示例是：行情交易日 `2026-09-10`，报告日 `2026-09-11`。

## 2. 环境变量

```bash
export FMP_API_KEY="<your_fmp_key>"
export INFOWAY_API_KEY="<optional_infoway_key>"
```

`FMP_API_KEY` 必填，用于指数、板块、行业热力和美债等数据。  
`INFOWAY_API_KEY` 可选，缺失时部分宽度、温度、盘后字段会被标记为缺失，不阻塞报告。

## 3. 数据流

```text
industry_mapping.json + FMP
      ↓ fetch_us_market_data.py
us_market_data_YYYY-MM-DD.json（含行业热力）

chain_universe.json + Yahoo/yfinance
      ↓ fetch_industry_chain_heat.py
industry_chain_heat_YYYY-MM-DD.json

us_market_data + industry_chain_heat
      ↓ fetch_daily_drivers.py
us_drivers_raw_YYYY-MM-DD.json
      ↓ 人工筛选 / 模型整理，不编造
us_drivers_YYYY-MM-DD.json

基础报告 + heat JSON + drivers JSON
      ↓ render_industry_chain_report.py / render_drivers_report.py
industry-chain-invest-wiki.md / industry-chain-invest-wiki-drivers.md
```

## 4. 运行命令

### 4.1 抓市场与行业热力

```bash
python3 scripts/fetch_us_market_data.py 2026-09-10 \
  --json-out data/us_market_data_2026-09-10.json
```

### 4.2 抓产业链行情并计算 65 段热力

```bash
python3 scripts/fetch_industry_chain_heat.py 2026-09-10 \
  scripts/chain_universe.json \
  data/industry_chain_heat_2026-09-10.json
```

### 4.3 生成驱动解释候选

```bash
python3 scripts/fetch_daily_drivers.py \
  --date 2026-09-10 \
  --market data/us_market_data_2026-09-10.json \
  --heat data/industry_chain_heat_2026-09-10.json \
  --out data/us_drivers_raw_2026-09-10.json
```

### 4.4 人工整理驱动解释

把 `us_drivers_raw_YYYY-MM-DD.json` 整理成：

```bash
data/us_drivers_YYYY-MM-DD.json
```

整理时保留 schema：`type`、`key`、`display`、`confidence`、`driver`、`sources`。没有明确公开原因时写：

```text
暂无明确公开原因。（置信度：低）
```

### 4.5 渲染热力版报告

`--base` 必须是已经包含 `### 2. Invest Wiki 产业链段热力` 章节骨架的报告。首次生成新报告时，先准备模板；复算当天报告时，可以用当前热力版报告作为 base。

```bash
python3 scripts/render_industry_chain_report.py \
  --base reports/us/2026-09-11-industry-chain-invest-wiki.md \
  --heat data/industry_chain_heat_2026-09-10.json \
  --out reports/us/2026-09-11-industry-chain-invest-wiki.md
```

### 4.6 渲染驱动解读版报告

```bash
python3 scripts/render_drivers_report.py \
  --base reports/us/2026-09-11-industry-chain-invest-wiki.md \
  --drivers data/us_drivers_2026-09-10.json \
  --out reports/us/2026-09-11-industry-chain-invest-wiki-drivers.md
```

### 4.7 校验并发布

```bash
python3 scripts/validate_report_data.py --market us \
  --report reports/us/2026-09-11-industry-chain-invest-wiki-drivers.md
```

发布前更新 `manifest.json`：

1. 把新报告 key 放到 `us` 数组最前。
2. 在 `us_title` 中加入标题。
3. 提交报告、manifest、数据产物。
4. push 后访问 `https://xifengxx.github.io/kol-daily/daily-briefing/index.html` 验证。

## 5. 当前仓库基线产物

| 文件 | 说明 |
|---|---|
| `data/us_market_data_2026-09-10.json` | 美东 9/10 市场快照，含 FMP 行业热力 |
| `data/industry_chain_heat_2026-09-10.json` | 美东 9/10 产业链热力，65 段全量计算 |
| `data/us_drivers_raw_2026-09-10.json` | 新闻候选原始结果 |
| `data/us_drivers_2026-09-10.json` | 人工整理后的驱动解释 |
| `reports/us/2026-09-11-industry-chain-invest-wiki.md` | 热力版报告 |
| `reports/us/2026-09-11-industry-chain-invest-wiki-drivers.md` | 热力 + 驱动解读版报告 |

## 6. 最低校验项

1. `chain_universe.json` 的 `version`、`logic_version`、`source_sha256`、`source_commit` 非空。
2. `industry_chain_heat` 的 `target_date` 与 `us_market_data` 的 `target_date` 一致。
3. `date_mixed=false`；如果为 `true`，报告必须标注混用原因。
4. 65 个 segment 全部出现在 JSON；报告只展示 Top8 / Bottom8。
5. `n_used >= 2` 的 segment 才参与排名。
6. 所有 `|chg_pct| >= 5%` 异常股进入驱动检索。
7. 不覆盖历史报告；需要重算时加版本后缀生成新文件。
