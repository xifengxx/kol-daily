## 一、模型发布/更新（AIHOT）

### 1. Qwen 发布 Qwen4-Max：2.4T 参数骨干、百万 token 上下文与长程智能体能力

**源站摘要**：Qwen 团队发布 Qwen4-Max，基于新 Qwen4 架构，拥有 2.4T 骨干参数、每 token 激活 71B、328B N-gram Embedding 参数，具备原生视觉能力和 100 万 token 上下文窗口。

**我的点评**：2.4T 总参数只激活 71B，说明仍走稀疏 MoE：把容量堆在专家里、把单 token 算力压住，再配 1M 上下文，目标明显是长程 agent 而非单轮问答。真正不常见的是 328B 的 N-gram Embedding——这部分吃显存，检索命中率会直接决定长上下文是否真能用。源站没给基准分数，能力边界暂时无法判断。[推测]（置信度：中）

**来源**：Qwen：Blog Retrieval（API） · [原始出处](https://qwen.ai/blog?id=qwen4-max) · [AIHOT 条目](https://aihot.news/items/nqcfrkilrh7nhnpd03t9q1zfh)

### 2. 腾讯混元发布 Hy4 flash：224B 总参数、1M 上下文的日常高性价比模型

**源站摘要**：腾讯混元推出 Hy4 flash，总参数 224B（含 64B Engram 参数）、激活 12B，支持多模态和 1M 上下文，API 价格大幅低于 Hy4（输入 0.5 元、输出 2 元每百万 tokens）。

**我的点评**：224B 总参数只激活 12B、外加 64B Engram，路线和 Qwen4-Max 同源：用记忆参数换有效容量，把推理成本压下去。输入 0.5 元、输出 2 元每百万 token，等于把 1M 上下文做成日用品价格。要验证的是 12B 激活在多模态与长上下文下会不会明显掉点——价格战的前提是质量别塌。[推测]（置信度：中）

**来源**：腾讯混元：Research（API） · [原始出处](https://hunyuan.tencent.com/research/100145?langVersion=zh) · [AIHOT 条目](https://aihot.news/items/u36vxmxeopbsx4if4lap30899)

### 3. Google 发布 Gemini 4 Carbon 与 Hydrogen，并推出 Decisions API 和自托管 agent 沙箱

**源站摘要**：Google 发布 Gemini 4 Carbon（gemini-4-carbon，1M 共享 token 池，11 月 30 日前 $2.00/$10.00 每 1M tokens。

**我的点评**：Carbon 与 Hydrogen 双线发布，真正的信息量在 Decisions API 和自托管 agent 沙箱：前者想把「模型做决策」变成可计费接口，后者等于承认 agent 必须在受控环境里执行。1M 共享 token 池加上 11 月 30 日前的 $2/$10 是典型获客价，之后按什么价格续费才决定真实成本，长期用户要按原价做预算。[推测]（置信度：中）

### 1. Microsoft Research 发布开源插件 TokenEconomizer，借仓库历史经验为 AI 编码 Agent 降本 18.4–30.9%

**源站摘要**：UC Berkeley、Microsoft Research 与 Microsoft Security 发布开源插件 TokenEconomizer，从 Agent 在同一仓库的历史会话中学习，在不修改 Agent 或底层模型的情况下降低后续会话成本。

**我的点评**：从同一仓库的历史会话里学「哪些上下文真有用」，不改 agent、不改模型就省 18.4–30.9%，这个增量很实在——coding agent 的成本大头本来就是重复读仓库和反复试错。可复现性的关键在冷启动：新仓库没有历史可学，效果会打折。开源插件比论文更有价值，能直接进 CI 做 A/B。[推测]（置信度：中）

### 1. Claude Code 团队如何设计 Agent 验证与测试流程

**源站摘要**：Anthropic Claude Code 团队分享其验证方法论，团队约 90% 的代码由 Claude 编写和审查，验证循环让并行运行数十上百个 Claude 成为可能。

**我的点评**：90% 代码由 Claude 写和审，能成立的前提不是模型强，而是验证循环被工程化：能自动跑的测试、能回滚的改动、能并行的任务边界。想复制这套方法的团队，最该先建的不是 prompt 库，而是「失败可观测」——否则并行几十个 agent 只是把错误放大几十倍。文章讲流程，落地成本在测试设施。[推测]（置信度：中）
