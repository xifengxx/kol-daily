## 一、产品发布/更新（AIHOT）

### 1. Mac 版 Gemini 应用上线计算机操作功能，可代用户执行跨应用任务

**源站摘要**：Google Labs VP Josh Woodward 宣布 Mac 版 Gemini 应用新增 computer use 功能，可跨文件夹、应用和网页代用户执行任务，屏幕和光标控制权仍归用户。官方演示显示 Gemini 能在后台窗口中点击、滚动和输入，把草图变成 Blender 里的绑定的 3D 模型。

**我的点评**：computer use 上桌面端，真正的门槛不是点击准确率，而是权限模型：跨文件夹、跨应用意味着把文件系统与登录态一起交给代理，任务中途失败的恢复与回滚成本远高于云端沙箱。官方强调控制权仍在用户手里，但「可随时接管」和「可审计复现」是两件事。Blender 建模更像能力展示，日常办公的长任务状态管理才是落地考题。（置信度：中）

**来源**：X：Josh Woodward (@joshwoodward, Google Labs VP) · [原始出处](https://x.com/joshwoodward/status/2123534862569324703) · [AIHOT 条目](https://aihot.news/items/h5xjk79bhcu8vgnbrynj208uj)

### 2. Google 在 Gemini API 推出 Tool Retrieval 预览

**源站摘要**：Google 在 Gemini API 的 Interactions API 中以预览形式推出 Tool Retrieval，让智能体按需加载工具参数 schema，而不是每次请求都发送完整工具库，以减少输入 token 并在工具数量扩大时保持选择准确。

**我的点评**：工具一多，全量塞 schema 就两头吃亏：输入 token 涨、选择准确率降。Tool Retrieval 本质是把工具选择也做成检索，方向对，但引入了一个新的失败模式——检索没召回，模型就不知道这个工具存在，而且不会报错。这种静默失败比调用报错更难查。预览阶段该盯的是召回率与漏检兜底，而不是省下多少 token。（置信度：中）

**来源**：Google Blog：AI（RSS） · [原始出处](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/) · [AIHOT 条目](https://aihot.news/items/n3npoqbr48wu58cke5p3ox18l)

### 1. OpenAI 详解 Codex 驱动的 Performance Factory 如何自动保持 ChatGPT 高性能

**源站摘要**：OpenAI 官方详解其 Performance Factory 系统，用 Codex 智能体在云端自动排查并修复 ChatGPT 的性能回归。其中 Regression Workflow 在三个多月内跟踪超过 1700 次调查、定位超过 600 个根因，相当于每天约 17 次自动调查。

**我的点评**：1700 次调查、600 个根因、日均约 17 次，这组数字的重点不是 Codex 多强，而是闭环完整：有遥测、有可复现的回归、有自动验证。多数团队抄不走这一段——没有稳定回归环境，让代理自动改代码只会把告警压下去、把问题埋起来。评估这类系统该看变更失败率有没有降，而不是调查次数涨了多少。（置信度：中）
