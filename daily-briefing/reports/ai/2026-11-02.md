## 一、行业动态（AIHOT）

### 1. OpenAI 12月起将ChatGPT与Codex合并为统一Token额度

**源站摘要**：作者引述OpenAI凌晨更新的帮助文档称，从12月开始Plus和Pro用户的ChatGPT聊天与Codex用量将合并为同一Token额度，仅Instant聊天不受影响。作者回顾此前按条数计费的历史、一个月内Codex Pro额度先降后恢复的运营反复，以及社区在GitHub上提issue抗议的反应，认为合并与IPO预期下的算力成本压力有关。

**我的点评**：合并额度的实质是把两种业务放进同一张计价表：聊天用得越重，留给编码的预算越少，反之亦然。这比直接降价更聪明——标价不动，重度用户自己收敛用量。作者把合并与 IPO 预期下的成本压力挂钩，但原文是公众号转述帮助文档，12 月细则仍以官方为准。真正的问题是折算方式：若聊天与编码的 token 单价不同，合并后用户几乎无法预估花费。此前 Pro 额度先降后恢复，已说明这类调整会消耗信任。[待核实]（置信度：中）

## 二、技巧与观点（AIHOT）

### 1. OpenRouter 教程：用 Responses API 构建可在 Linux 沙箱验证 bug 的 AI 代码审查脚本

**源站摘要**：OpenRouter 发布教程，介绍一个 233 行、仅用标准库的 review.py，通过 Responses API 组合 Files API、Shell 沙箱工具和 Apply Patch 工具，把变更文件上传到托管 Linux 沙箱，让模型实际运行检查确认 bug 并返回 V4A 补丁。

**我的点评**：值得注意的不是「AI 审代码」，而是把审查结论放到可执行沙箱里验证：模型真的跑起来确认 bug 再给补丁，判断依据从措辞变成可观察结果。233 行、只用标准库，接入成本极低，适合塞进 CI 或开源项目的 PR 流程。限制在沙箱保真度——依赖、外部服务、数据库状态都与真实环境有差距，跑通不等于没问题；把不可信仓库的代码交给托管沙箱执行，安全边界也得自己兜。[推测]（置信度：中）

**来源**：OpenRouter：Announcements（RSS） · [原始出处](https://openrouter.ai/blog/tutorials/ai-code-review/) · [AIHOT 条目](https://aihot.news/items/yww15c701iat30p8ttjf029ij)

### 2. Claude Code 技巧：任务变难时输入 ultrathink 提升当前回合推理努力

**源站摘要**：Addy Osmani 分享 Claude Code 技巧：当任务比预期更难时，在 Claude 工作期间输入 ultrathink，可提升该回合剩余部分的推理努力，该功能适用于最新版本的终端。他引用 @dmwlff 的帖子，其中提到 ultrathink 已回归 Claude Code CLI，此前因显得怪异且可能令人困惑曾被关闭。

**我的点评**：这个技巧的价值在「中途加力」而非重新提问：看到模型理解偏了、任务比预期难，可以在同一回合抬高推理预算，省掉重述上下文的成本。它反映推理强度正从模型固定参数变成可调旋钮——用户按难度付费。但它是社区口口相传的终端行为，官方文档是否覆盖、会不会随版本变化都不确定；团队流程里不宜依赖这种非显式配置，更稳的做法仍是先规划再执行。[待核实]（置信度：中）
