### 1. 腾讯开源模型 Hy4 Flash 上线 Fireworks serverless

**源站摘要**：腾讯新开源模型 Hy4 Flash 现已在 Fireworks serverless 上可用。该模型为 MoE 架构，总参数约 220B、每 token 激活约 12B，1M token 上下文窗口（Fireworks 上线时为 512K），支持文本和图像输入，面向文档处理、研究、办公和 Agent 工作流。

**我的点评**：220B 总参数、12B 激活的稀疏 MoE，推理成本接近 12B 稠密模型，这是当下长上下文模型最务实的路线。1M 上下文在 Fireworks 上线时砍到 512K，恰好说明瓶颈不在模型而在 KV cache 的显存与并发成本。对腾讯，借 Fireworks serverless 出海绕开了自建算力；对使用者，512K 能否撑住文档级检索才是选型依据，而不是 1M 这个标称值。（置信度：中）

### 1. Anthropic 复盘 Messages API 从 Python 迁移到 Rust 的校验方法

**源站摘要**：Anthropic 介绍如何将 Messages API 从 Python 迁移到 Rust，并把生产系统本身当作校验器。该 API 流量从 2024 年初到 2026 年秋增长约 1800 倍，迁移后每请求 CPU 降低约 70%，首 token 中位时间缩短约 20%，且未停服或冻结功能开发。

**我的点评**：把生产系统当校验器是这次迁移真正的可复用点：新旧实现并行跑真实流量、逐层比对响应，才能做到不停服也不冻结功能。CPU 降 70%、首 token 中位快 20% 是结果，前提是先定义清楚「等价」的判定标准。难点在非确定性输出——采样、工具调用、流式分块都难以逐字节比对，Anthropic 大概做了分层抽样校验，源站没展开。[推测]（置信度：中）

**来源**：Anthropic：Research（发表成果 · 网页） · [原始出处](https://www.anthropic.com/research/migrating-api-to-rust) · [AIHOT 条目](https://aihot.news/items/h1ja45355xx1xf9rqf89cv1if)

### 2. 上下文漂移如何影响你的 AI Agent：470 项实验与一个免费的 MCP 解法

**源站摘要**：Google AI 开发者 Patrick Kelly 通过 470 个任务实测区分 context rot 与 context drift，在 Gemini 3.8 Flash 和 Gemini Pro 的沙盒中发现：模型在 73% 的运行中内部察觉文件冲突，但 0% 会主动告知用户，95%-100% 的情况下任务级 skill 文件会覆盖 AGENTS.md 的严格规则。

**我的点评**：最刺眼的是 0%：模型在 73% 的运行里内部察觉文件冲突，却一次都不主动报告，这直接推翻「模型会自己纠错」的假设。95%-100% 的 skill 覆盖 AGENTS.md 说明上下文里的规则是「后到者赢」，而非按权威层级——对所有靠 AGENTS.md 做约束的团队都是坏消息。用 MCP 做冲突检测，本质是把「该不该说」从模型判断变成系统强制，值得马上试。（置信度：高）

**来源**：Google AI：DEV 作者专属（RSS） · [原始出处](https://dev.to/googleai/how-context-drift-impacts-your-ai-agents-1iph) · [AIHOT 条目](https://aihot.news/items/br6usy3mxv1q0mzxhgf9y8qam)
