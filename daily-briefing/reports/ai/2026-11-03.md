### 1. Claude Platform 推出 message threads 公测，降低长会话智能体延迟

**源站摘要**：Anthropic 在 Claude Platform 推出 message threads 公测，智能体每轮只需发送新增消息而无需重发全部对话历史，从而缩短首 token 时间。

**我的点评**：message threads 的价值不在省带宽，而在把「会话状态」从客户端搬到服务端：每轮只传增量，长任务的上下文管理交给平台。这直接缓解 agent 最贵的两项开销——重复 prefill 带来的首 token 延迟与输入 token 账单。但它把无状态 API 变成有状态资源，会话生命周期、并发上限和跨区域一致性会成为新的运维约束，公测期值得先压测长会话的失败恢复。（置信度：中）

## 三、论文研究（AIHOT）

### 1. OpenAI 训练并部署激活分类器作为前沿模型安全监控层

**源站摘要**：OpenAI 自 GPT-5.6 起在其最强模型的内部和外部流量上部署激活分类器（probes），利用模型内部激活逐 token 实时评分，可在生成中途阻断违规回复和工具调用并交由推理模型复审。实验显示 probes 比更大的文本分类器对测试的越狱攻击更鲁棒，准确率随模型能力提升，且在后训练各检查点间迁移良好，但需为新基础模型重新训练，且只能检测可显式训练的已知违规类型。

**我的点评**：用内部激活做逐 token 评分，比输出侧文本分类器更早介入——能在生成中途阻断违规回复和工具调用，这是 agent 时代安全的关键差别。可迁移性与随能力提升的准确率是亮点，但两个边界很硬：换基础模型要重训，且只能覆盖可显式训练的已知违规类型，对新型越狱仍是零样本。它更像一层廉价高频的初筛，而非替代红队与推理模型复审。（置信度：中）

## 四、技巧与观点（AIHOT）

### 1. 数字生命卡兹克分享折腾一年的Agent自动化系统架构

**源站摘要**：自媒体作者卡兹克分享自己搭建近一年的Agent自动化系统，核心是把任务起点从人身上移开，由事件触发Agent工作。系统分为自动化中台、Agent执行、CI中台和飞书决策四层：中台用rules.json统一管理事件触发和Agent调度，本地MacMini跑Agent任务，自建CI中台完成审查、检查、合并、发布、核实五步，只在删数据、花钱、改方向等关键决策时通过飞书卡片找作者拍板。

**我的点评**：这套架构最值得抄的不是四层划分，而是「事件触发 + 关键决策才找人」的边界设定：删数据、花钱、改方向才拍板，其余交给 CI 的五步闭环。它把 agent 的不确定性关进可审查的流水线，而不是指望模型自觉。代价是前置投入高——rules.json 的触发规则与被审查的 CI 都要长期维护，个人开发者很难一开始就摊平成本。（置信度：中）
