### 1. OpenAI 正式发布 Decisions API，面向低延迟低成本小决策

**源站摘要**：OpenAI 宣布基于 GPT-6 Luna 的 Decisions API 正式可用，用于分类、路由、评分等有界答案问题，速度最高比通过 Responses API 使用 GPT-6 Luna 快 10x。

**我的点评**：把「分类、路由、评分」单独做成 API，本质是把通用接口按延迟与成本分层——底座仍是 GPT-6 Luna，快 10x 更可能来自更短的输出路径和专用解码，而不是模型变聪明。真正值得看的是计价单位：这类有界任务按「决策」计价才合理，按 token 计价会与本地小模型直接比成本。产品价值还取决于能否暴露置信度或分数分布，否则阈值调优仍要自己兜底。[待核实]（置信度：中）

### 2. Claude 网页、桌面和移动端将默认启用 auto mode

**源站摘要**：Claude 官方宣布，下周起 Pro、Max 和 Team 套餐在 Claude 网页、桌面和移动端应用中的会话将默认以 auto mode 运行。auto mode 不再逐步请求用户批准，而是由自动检查拦截高风险操作，用户可随时切回手动模式。其引用的 Claude Code 更新提到 auto mode 用独立分类器审查 shell 命令，测试中拦截了 89% 的危险命令，手动批准为 14%。

**我的点评**：把 auto mode 设为默认，等于把「要不要批准」这个判断从用户手里收回到厂商的分类器里。89% 拦截率看着高，反过来意味着仍有一成危险命令被放行；手动批准 14% 更说明多数人是无脑点同意——这组对照其实在论证「人不可靠」，而非分类器足够好。要盯的是误报带来的摩擦与责任归属：自动放行造成的损失由谁承担。快照未给按仓库或按项目的关闭粒度。[待核实]（置信度：中）

### 3. Replit 发布 Monitoring Agent，为应用提供可自动修复并部署的值班智能体

**源站摘要**：Replit 发布 Monitoring Agent，为应用提供相当于自主值班工程师的监控智能体。它可以读取生产日志和指标调查错误、变慢和部署失败，在启用 autofix 后验证修复并邮件汇报，启用 auto-publish 后可自动部署修复。该能力建立在早前上线的 App Monitoring 之上，用户可在应用的 Publishing 设置中开启。

**我的点评**：监控 agent 的关键不是能不能查到错误，而是敢不敢直接改生产——autofix 加 auto-publish 把「值班工程师」变成了「变更发起者」，风险从漏报转成误改。决定能不能用的是灰度与回滚链路：修复若不能在影子环境验证、不能一键回退，自动部署就是拿线上做实验。它对没有专职运维的小团队价值最大，对数据敏感业务则必须先设审批门槛。快照未说明权限边界与回滚机制。[待核实]（置信度：中）
