### 1. Anthropic 开启 Claude Duet 研究预览，Claude 以主动式智能体接管日常工作

### 2. OpenAI API 支持 12 小时 prompt 缓存，Codex 与 Work 用户缓存永久保留

**源站摘要**：OpenAI 开发者账号宣布 API 现已可选 12 小时 prompt 缓存，持续运行的智能体可在请求间隔数小时的情况下继续以更低的缓存输入费率复用指令、工具和上下文。Tibo 补充称，Codex 与 Work 中已登录用户的缓存会永久保留，返回旧对话或数小时后恢复会话保证命中缓存，且无额外惩罚。

**我的点评**：缓存时长其实是在给 agent 的空闲期定价：多数 agent 循环的瓶颈不是算力而是人，一次审批可能隔几小时，缓存过期就得重付整段前缀。12 小时基本覆盖一个工作日的人机协作节奏。更值得注意的是 Codex/Work 登录用户「永久保留」——上下文越久不失效，迁移成本越高，这是典型的锁定设计，同时也意味着用户数据在服务端长期留存，隐私口径要另看。快照没给缓存容量与计费细节。[待核实]（置信度：中）

### 1. Microsoft Research 与合作者证明 31 年历史的 KLS 猜想

**源站摘要**：Microsoft Research 的 Xinzhi Zhang 与 Zhao Song 证明 1995 年提出的 Kannan–Lovász–Simonovits（KLS）猜想，表明对数凹分布的最优平面切割与任意形状切割的差距不随维度增长，以普适常数为界。

**我的点评**：KLS 猜想说的是：对数凹分布下，最优超平面切割与任意形状最优切割的差距，有一个与维度无关的普适常数上界。它被追了 31 年，是因为高维几何里几乎所有采样与体积估计的复杂度分析都隐式依赖这类等周性质——热传导、hit-and-run、Langevin 的收敛界都能往上挂。证明本身是纯数学结果，短期不会变成工程提速，但它把「高维下平面切割够用」从猜想变成定理。具体证明路线与常数大小快照未给。（置信度：中）

**来源**：Microsoft Research 博客（RSS） · [原始出处](https://www.microsoft.com/en-us/research/blog/solving-a-31-year-old-grand-challenge-in-mathematics-the-kls-conjecture/) · [AIHOT 条目](https://aihot.news/items/y1fd2c0s3ydociygdah7apvme)

## 五、技巧与观点（AIHOT）

### 1. 编程 Agent 增长遭遇人类评审瓶颈：Tessl 博客解析信任赤字

**源站摘要**：Tessl 博客引用 Jellyfish 2026 年 9 月 AI Engineering Trends 数据指出，中位数公司已有 22% 的合并 PR 由自主编码 Agent 撰写（90 分位达 53%），但仅约 0.6% 的 PR 由 Agent 评审合并（前 10% 公司为 9%）。

**我的点评**：22% 的合并 PR 由 agent 写、只有 0.6% 由 agent 评审合并，这个三十倍以上的落差就是「信任赤字」的量化版本。它说明生成侧产能已经上来，评审侧还完全靠人，于是人成了吞吐上限——瓶颈从写代码挪到了读代码。前 10% 公司做到 9% 的 agent 评审，说明这道墙不是不可移动，但需要配套的测试与回滚机制才敢放手。对团队的启示：先投资可验证性，再谈提高 agent 的合并比例。（置信度：中）
