**源站摘要**：Wiz Research 与 Ikotas Labs、Rapid7 等团队独立发现 NGINX 两个 Critical 远程代码执行漏洞，CVSS 4.0 评分 9.2，已与 F5 协调并于 2026-11-18 发布修复。

**我的点评**：CVSS 4.0 9.2、无需认证、走 HTTP/2 路径，这三个条件叠加意味着暴露在公网的 NGINX 边缘节点要按「可蠕虫」级别处理。三家团队独立发现同一类问题，通常指向协议解析层的结构性缺陷，而非单个配置错误[推测]。CVSS 4.0 与 3.1 不可直接比较；先盘点 HTTP/2 是否开启并打补丁，WAF 对这类漏洞并不可靠。（置信度：中）

### 2. OpenAI 发布研究加速报告：智能体完成近半数长时研究任务但进展参差

**源站摘要**：OpenAI 发布第二份研究加速报告，基于内部测量介绍编码智能体如何改变 AI 研发周期。3 月到 10 月，估计需 2-4 小时的人工任务智能体自主成功率从 23% 升至 46%，4-8 小时任务从 13% 升至 35%；但任务间差异明显，监控训练成功率达 79%，而推理与服务栈编码仅 25%。

## 五、技巧与观点（AIHOT）

### 1. Anthropic 工程师复盘用 chaos loop 强化 Claude Docs 上线：20 亿次请求仅 60 次服务器错误

**源站摘要**：Anthropic 工程师 Vivek Nair 复盘 Claude Docs 9 月 16 日上线前的 chaos loop 实践：让 Claude Code 会话在镜像生产的 staging 集群上以每天超 100 万合成 docs 持续压测并修复故障，峰值时同时运行 30 个 sub-agents。

**我的点评**：可复用的不是「30 个 sub-agent」这个数字，而是把 agent 放进镜像生产的 staging、用合成流量持续制造故障、再让它自己修的闭环。20 亿请求 60 次服务器错误听着漂亮，但「服务器错误」的口径没给，超时、限流、数据错乱未必计入。它适合无状态 API；有状态、不可逆的业务不能照搬。（置信度：中）

**来源**：Anthropic：Claude.dev 开发者博客（RSS） · [原始出处](https://claude.dev/blog/chaos-loop-claude-docs-launch/) · [AIHOT 条目](https://aihot.news/items/snkvsiff90slvj17hf9i5u4do)
