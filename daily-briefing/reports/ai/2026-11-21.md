### 1. Thinking Machines Lab 发布可跑在笔记本上的开源权重模型 Inkling 2 Mini

**源站摘要**：Thinking Machines Lab 发布开源权重模型 Inkling 2 Mini，采用循环 Transformer 架构，将中间 12 层每 token 运行三次，总参数 26.4B、激活 3.4B，内存占用约 20GB，可在 32GB 内存以上的 Mac 本地运行。

**我的点评**：循环 Transformer 把中间 12 层每 token 跑三次，等于用更多串行算力换参数效率：26.4B 总量只激活 3.4B，约 20GB 内存就能上 32GB Mac。真正的看点不是「能跑」，而是单位显存下的有效深度——这对推理链更友好，但吞吐会明显低于同参数量稠密模型。源站没给量化方式和 tokens/s，本地体验能否成立还要看这两项。[待核实]（置信度：中）

## 四、技巧与观点（AIHOT）

### 1. Runway 详解如何构建智能体驱动的软件工厂

**源站摘要**：Runway 介绍了逐步把软件交付各环节交给智能体完成的实践。智能体 10 月驱动了 38% 的合并 PR（6 月仅 0.1%），首次批准等待中位数从超过 2 小时降至约 5 分钟；AI 单独批准的 PR 回滚率约千分之一，低于人工批准的约 1/200。

**我的点评**：38% 的合并 PR 由 agent 驱动，这个数字本身不稀奇；稀奇的是回滚率约千分之一，低于人工的约 1/200。若口径成立，说明 agent 在「低风险、可自动验证」的改动上已经越过人类基线，瓶颈从写代码转到定义任务和验收。要小心的是分母：38% 很可能集中在格式化、依赖升级、测试补齐这类窄任务，不能外推到核心架构改动。（置信度：中）

**来源**：Runway：News（网页） · [原始出处](https://runwayml.com/news/engineering/building-a-software-factory) · [AIHOT 条目](https://aihot.news/items/wnw22hxqlwsd58lzsm44psc6g)

### 2. DeepSeek Harness 发布100天，作者分享13个实用插件玩法

**源站摘要**：卡兹克在DeepSeek Harness发布100天之际分享了13个插件玩法。

**我的点评**：发布 100 天就有 13 个插件玩法被系统整理，说明 Harness 的生态开始从「能用」走向「按工作流定制」。插件真正的价值不是多一个按钮，而是把团队约定（lint、评审、发布检查）固化进 agent 的执行路径，减少每次重新提示的漂移。对个人用户，先挑与自身高频流程重合的两三个，别一次装完——插件越多，失败面越大。（置信度：中）

**来源**：X：卡兹克 (@Khazix0918) · [原始出处](https://x.com/Khazix0918/status/2123627885730951241) · [AIHOT 条目](https://aihot.news/items/amx0tnq9rthd6ssx81np25ldc)

### 3. OpenHands 详解用 Agent 自动修复自家镜像 CVE 的软件工厂

**源站摘要**：OpenHands 团队详解把大部分 CVE 修复工作交给 Agent 流水线的做法：Agent 选择修复、开 PR、合并低风险项并跟踪到部署，人每天只读一条最多 11 行的 Slack 消息和少量 PR。

**我的点评**：CVE 修复是 agent 的理想场景：有扫描器和测试做自动验收，改动边界清晰，失败可回滚。OpenHands 的关键设计不是「让 agent 修」，而是只自动合并低风险项、其余留给人，人每天只看一条极短的摘要——把注意力从「读所有 PR」压到「异常才介入」。风险在漏报和供应链投毒，自动合并策略必须配独立的依赖审计。（置信度：中）
